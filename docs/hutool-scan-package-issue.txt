标题：
ClassScanner 扫描后关闭 Spring Boot 共享 NestedJarFile，导致后续读取报 Zip file closed（5.x、6.x 均可复现）

正文：

JDK版本：OpenJDK 17.0.19
hutool版本：5.8.48、6.0.0-M22
Spring Boot Loader版本：3.3.1

### 问题描述（包括截图）

通过 Spring Boot 可执行 JAR 运行时，ClassUtil.scanPackageBySuper() 扫描包（包括 BOOT-INF/classes 或 BOOT-INF/lib 下的嵌套 JAR）后，会关闭 Spring Boot 共享的 NestedJarFile，导致已有连接后续访问该对象时报错：

```text
java.lang.IllegalStateException: Zip file closed
```

整个复现过程在 main 方法中顺序执行：先取得 JAR 对象，再执行 Hutool 扫描，最后通过已有连接读取 JAR，即可触发异常。

#### 1. 复现代码

完整 demo：

- Hutool 5.8.48：https://github.com/seavers/hutool-scan-package-bug/tree/master
- Hutool 6.0.0-M22：https://github.com/seavers/hutool-scan-package-bug/tree/hutool6

demo 为单模块 Spring Boot 项目（使用 spring-boot-starter-parent 3.3.1），无需多模块，打包后类文件位于 BOOT-INF/classes，通过 LaunchedClassLoader 访问时由 NestedJarFile 提供底层支持。

以下为简化的业务调用示例（6.x）：权限定义分散在多个枚举中，通过扫描自动发现实现类，再根据请求中的权限键查找定义。

```java
import demo.permissions.PermissionKey;
import org.dromara.hutool.core.reflect.ClassUtil;

public class PermissionValidator {
    public static void main(String[] args) {
        System.out.println(checkPermission("ai#generate_title#generate#web"));
        System.out.println(checkPermission("ai#generate_title#generate#app"));
    }

    static PermissionKey checkPermission(String key) {
        // 自动发现权限枚举，查找请求对应的权限定义。
        for (Class<?> type : ClassUtil.scanPackageBySuper("demo.permissions", PermissionKey.class)) {
            if (type.isEnum()) {
                for (Object value : type.getEnumConstants()) {
                    PermissionKey permission = (PermissionKey) value;
                    if (key.equals(permission.getKey())) {
                        return permission;
                    }
                }
            }
        }
        throw new IllegalArgumentException("权限不存在：" + key);
    }
}
```

上述代码用于演示通过扫描自动发现权限枚举的实际业务场景（假设权限枚举中分别定义了 #web 和 #app 两种权限键）。

需要说明的是，单纯顺序调用两次扫描方法并不会直接抛出异常（每次新建连接会由 Spring Boot 打开新的 JAR 实例）；问题的根因在于 Hutool 扫描结束后静默关闭了共享的 NestedJarFile 对象，导致在此之前已建立连接并持有该对象的外部调用方后续在访问 JAR 时报 Zip file closed。完整复现工程见上述仓库。下面的运行结果来自完整 demo。

5.x 对应使用 cn.hutool.core.util.ClassUtil。

运行完整 demo：

```bash
mvn -B clean package
java -jar target/hutool-scan-package-bug-1.0-SNAPSHOT.jar
```

需要通过 java -jar 运行。从 IDE 直接运行 main，会使用普通 classes 目录，不具备嵌套 JAR 的触发条件。

#### 2. 运行结果

5.8.48 和 6.0.0-M22 均出现以下结果：

```text
包 URL=jar:nested:/.../target/hutool-scan-package-bug-1.0-SNAPSHOT.jar/!BOOT-INF/classes/!/demo/permissions
JAR 类型=org.springframework.boot.loader.net.protocol.jar.UrlNestedJarFile，共享同一对象=true
[第一次调用] 扫描前读取成功，条目=demo/
[第 1 次扫描] Hutool 扫描完成，发现类=[class demo.permissions.AiPermissionKey]
[第二次调用] 已有连接仍持有旧 JAR=true
[第二次调用] 读取失败，异常=java.lang.IllegalStateException: Zip file closed
java.lang.IllegalStateException: Zip file closed
    at org.springframework.boot.loader.jar.NestedJarFile.ensureOpen(NestedJarFile.java:414)
    at org.springframework.boot.loader.jar.NestedJarFile.entries(NestedJarFile.java:175)
```

对照验证：

- 跳过 Hutool 扫描，通过已有连接再次读取正常。
- 扫描结束后重新建立连接，Boot 返回新的 JAR 对象，读取及再次扫描正常。

触发问题的关键是：已有连接仍持有被 Hutool 扫描关闭的旧 JAR 对象。

#### 3. 原因定位

5.8.48 中，ClassScanner 的调用链为：

```text
scan()
  → scanJar(URLUtil.getJarFile(url))
  → finally: IoUtil.close(jar)
```

6.0.0-M22 中，调用链为：

```text
scan()
  → scanJar(new JarResource(url).getJarFile())
  → finally: IoUtil.closeQuietly(jar)
```

6.x 的 JarResource 仍通过 JarURLConnection.getJarFile() 获取 JAR。

两个版本均未区分自行创建的 JAR 与 URL 连接返回的共享 JAR，扫描完成后统一关闭，导致已有连接持有的对象失效。

#### 4. 影响范围

在 6.0.0-M22 中，还分别验证了以下入口，均会关闭共享 JAR：

- ClassUtil.scanPackage() 及指定包、过滤器重载。
- ClassUtil.scanPackageBySuper()、scanPackageByAnnotation()。
- ClassScanner 对应的静态扫描方法。
- ClassScanner.scanAllPackage()、scanAllPackageBySuper()、scanAllPackageByAnnotation()。
- ClassScanner 实例方法 scan()、scan(false)、scan(true)。

这些入口最终共用 scanJar()。即使过滤器没有匹配任何类，共享 JAR 也会被关闭。

#### 5. 预期行为

扫描结束后，应释放扫描器自行创建并拥有的 JAR 资源，同时避免关闭 Spring Boot 类加载器或其他连接仍在使用的共享 JAR。
